# 研发人员开通、变更与离职回收

研发访问采用**个人身份、按岗位授权、定期复核**。申请和回收覆盖 GitHub、Azure/ACR、开发主机、网关配置、监控平台以及应用测试环境。共享平台管理员权限与应用开发权限分开。

## 入职开通

1. 直属经理提交人员姓名、岗位、项目、开始日期和预计结束日期；系统负责人确认所需资源。
2. IT 开通公司身份与多因素认证；GitHub 加入对应团队，而不是逐仓库手工授予广泛权限。
3. 平台负责人按环境授权 Azure：开发者默认 Dev 资源只读或所需操作权限；ACR 默认拉取，推送由 CI 身份执行。
4. 需要 Ubuntu 主机时分配唯一 `balcoNN` 账号并登记人员映射，详见[服务器基线](/zh/infrastructure/04-server-baseline)。
5. 首次登录后核对仓库、Dev 环境、日志与开发工具；记录开通工单和批准人。

## 权限矩阵

| 身份 | GitHub | Azure/ACR | Prod |
| --- | --- | --- | --- |
| 开发者 | 项目仓库 Write | Dev 所需权限；ACR Read/Pull | 默认无直接部署权 |
| 项目维护者 | 项目仓库 Maintain | Dev/Test 所需权限 | 通过审批后的流水线发布 |
| 平台管理员 | 平台仓库和设置 Admin | 平台资源管理 | 应急操作需记录 |
| 外部协作者 | 指定仓库或项目最小权限 | 默认无 | 无 |


## 岗位变更与离职

岗位变化先撤销旧项目和旧环境权限，再开通新权限。收到离职通知当日撤销 GitHub 组织和仓库访问、Azure 角色、ACR 权限、VPN/主机账号、密钥库与监控平台权限；清点个人 PAT、SSH key、应用注册凭据及在其名下的自动化任务。交接仓库所有权、告警联系人和未完成发布。

平台负责人每季度导出成员与角色清单，由项目负责人确认继续保留的访问。异常权限、无人负责的服务身份和过期外部协作者纳入清理记录。
