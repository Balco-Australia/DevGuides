# Ubuntu 服务器基线

本规范适用于 Balco 自行管理操作系统的物理机和虚拟机。Azure App Service、Static Web Apps 与 Container Apps 的宿主系统由 Azure 管理，不按本页执行主机安装。当前订阅未列出 Azure VM；[资源清单](./01-resource-inventory.md)中的两台物理机是演示数据，不代表已按本规范部署。

## 1. 操作系统与安装 

- 新建主机统一安装 **Ubuntu Server 24.04 LTS，64 位**，使用官方安装介质或经过校验的内部镜像。例外版本须记录兼容性原因和升级计划。
- 安装时选择最小化组件、UEFI 启动和 GPT 分区表；主机名采用 `balco-<env>-<role>-<nn>`，例如 `balco-dev-build-01`。
- 安装后记录主机序列号、Ubuntu 版本、内核、CPU、内存、磁盘、MAC 地址、管理 IP、环境和负责人；启用时间同步与安全更新。
- 新主机交付前完成补丁、账户、SSH、磁盘、网络、防火墙、监控及备份检查。

[Ubuntu 官方维护周期](https://ubuntu.com/security/esm)显示 24.04 LTS 仍处于标准支持期。升级到新的 LTS 版本先在 Test 验证应用兼容性，再更新此基线。

## 2. 用户与权限

| 账户 | 用途 | 权限 |
| --- | --- | --- |
| `balcoadmin` | 平台管理员执行安装、补丁和故障处理 | 可使用 `sudo`；不运行日常业务进程 |
| `balco01` | 分配给第一位研发或运维人员的日常登录账户 | 普通用户，默认无 `sudo` |
| `balco02` | 分配给第二位研发或运维人员的日常登录账户 | 普通用户，默认无 `sudo` |
| `balco03`… | 后续人员按编号递增 | 普通用户，权限按岗位申请 |
| 应用服务账户 | 运行单个服务或定时任务 | 无交互登录，仅可访问自身目录和数据 |

- `balcoNN` **一人一号**，资产台账记录编号对应人员、申请单和停用日期；不得多人共用，也不得把离职人员的编号立即转给新人。
- `balcoadmin` 的密钥由平台管理员管理，使用须留下操作记录。日常操作优先使用个人 `balcoNN` 账户；确需提权时审批并限时加入 `sudo` 组。
- 禁用 SSH 密码登录与 root 直接登录，使用个人公钥。人员离职或岗位变更时撤销账户、SSH key 和临时提权。
- 系统服务使用独立服务账户，不使用 `balcoadmin` 或个人账户运行。

## 3. 磁盘与分区

新主机建议使用不小于 **100 GiB 系统盘**，GPT + LVM + ext4。容量按工作负载调整，但系统、日志和业务数据必须分离。

| 挂载点 | 初始容量 | 用途与规则 |
| --- | --- | --- |
| EFI System Partition | 1 GiB | UEFI 启动 |
| `/boot` | 2 GiB | 内核与启动文件 |
| `/` | 40 GiB | 操作系统和系统软件 |
| `/var` | 20 GiB | 软件状态与缓存，不存放无限增长的应用数据 |
| `/var/log` | 10 GiB | 系统日志，启用轮转与容量告警 |
| swap | 4 GiB | 缓冲异常内存压力，不替代内存扩容 |
| LVM 未分配空间 | 余量 | 为系统扩容保留 |

业务数据挂载到独立数据盘的 `/srv/<service>`；若运行 Docker，将 `/var/lib/docker` 放在独立数据卷，避免镜像和容器日志耗尽根分区。加密、RAID 与文件系统选择由数据敏感度和恢复目标决定。交付时记录磁盘序列号、容量、挂载点、文件系统和备份方式。

## 4. 网络划分

以下 CIDR 是**新环境的规划示例**，实施前必须与现有企业网络和 Azure VNet 核对，避免地址冲突。

| 网络区域 | 示例网段 | 放置对象 | 默认访问规则 |
| --- | --- | --- | --- |
| 管理区 | `10.20.10.0/24` | 跳板机、运维入口 | 仅管理员经 VPN 或跳板机访问主机 SSH |
| Dev 区 | `10.20.20.0/24` | 开发主机与服务 | 可访问批准的开发依赖，不直连 Prod 数据 |
| Test 区 | `10.20.30.0/24` | 测试主机与服务 | 仅访问测试数据与经批准的共享服务 |
| Prod 应用区 | `10.20.40.0/24` | 正式应用主机 | 只开放网关和必要的下游端口 |
| 数据区 | `10.20.50.0/24` | 数据库与存储 | 仅接受指定应用区和备份服务访问 |

每台主机使用固定管理地址或 DHCP 保留地址，并登记 DNS、网关和防火墙规则。SSH 22 端口不向互联网开放；Dev/Test 到 Prod 默认拒绝。应用对外入口优先经受控网关，不直接暴露主机端口。网络、DNS 与证书的统一规范后续编写于[网络、DNS、证书与 TLS](./06-network-and-dns.md)。

## 5. 维护与验收

普通补丁每月评估并安排维护窗口；已被利用或影响对外服务的高危漏洞目标在 7 天内修复或实施隔离。主机监控 CPU、内存、磁盘、网络与时间同步；日志集中收集，系统和数据按[备份规范](./08-storage-and-backup.md)执行。

交付验收至少包含：Ubuntu 版本正确、账户和 SSH key 已登记、root/密码登录关闭、分区和挂载点符合设计、网络规则经核对、监控与备份实际触发一次、恢复责任人明确。偏离基线须记录原因、负责人、补偿措施和到期日。
