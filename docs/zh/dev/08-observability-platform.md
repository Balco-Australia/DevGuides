# 集中日志、指标、链路追踪与告警平台

Dev 层提供统一的可观测平台：Azure 工作负载优先接入 **Azure Monitor、Application Insights 与 Log Analytics**；自管 Nginx 和 Ubuntu 主机通过集中采集进入同一检索与告警体系。APP 层负责定义业务指标与应用告警，Infrastructure 层负责主机与资源可用性。

## 日志规范

每条应用日志至少包含 UTC 时间、环境、系统、服务、版本、级别、消息和关联 ID；HTTP 请求另记方法、路由、状态码与耗时。日志使用结构化字段，便于按一次请求贯穿网关、API 和下游调用。Nginx 保留访问与错误日志，Ubuntu 主机收集系统和安全事件。

不记录密码、访问令牌、完整个人信息或业务敏感正文。需要定位用户时使用受控的用户标识或脱敏字段。日志读取权限按岗位授予；生产日志访问要留审计记录。

## 指标与告警

| 对象 | 基础信号 | 默认处理人 |
| --- | --- | --- |
| Nginx 网关 | 可用性、5xx、上游连接失败、证书到期 | 平台负责人 |
| API / Web | 请求量、错误率、延迟、关键依赖失败 | 应用负责人 |
| Container Apps Job | 执行成功率、失败次数、运行时长 | 任务负责人 |
| Azure/Ubuntu 基础资源 | CPU、内存、磁盘、备份结果 | 基础设施负责人 |

告警配置记录阈值、严重级别、通知组、值班人、处理手册和关闭条件。初版告警以**服务不可用、持续错误、任务失败、备份失败、证书即将到期**为重点；启用前用测试事件验证通知能送达。平台每月检查无人接收、重复和长期静默的规则。

## 保留与验证

Dev 日志默认保留 14 天，Test 保留 30 天，Prod 运营日志保留 90 天；审计日志的期限由数据分类与合规要求单独确定。上述期限是初版目标，启用前核对 Azure 成本和现有工作区策略。发布后用一次可追踪请求验证日志、指标和关联 ID，再以测试告警验证通知链路。
