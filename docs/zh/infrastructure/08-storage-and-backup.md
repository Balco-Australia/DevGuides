# 存储、备份与保留

备份策略按**数据重要性和恢复目标**制定，不能只看资源是否由 Azure 托管。当前 `balco-poc` 中有 App Service、Static Web Apps、Log Analytics、Container Registry 和 Container Apps Job；这些资源的配置、镜像、日志及业务文件具有不同的恢复方式。

## 各类资源的恢复材料

| 资源 | 需要保留或重建的内容 | 最低验证方式 |
| --- | --- | --- |
| 前端和 API | 源码、构建产物、部署配置、环境变量名 | 从仓库重新构建并部署到非生产环境 |
| Azure 资源 | IaC、资源参数、权限与网络设置 | 通过 `what-if` 或同等方式验证可重建 |
| 容器任务 | 镜像摘要、任务定义、输入与输出文件 | 使用样本任务完成一次恢复运行 |
| 业务数据 | SharePoint、数据库或文件存储中的正式数据 | 按对应应用的 RPO/RTO 做恢复演练 |
| 日志 | 诊断与审计记录 | 查询历史事件并核对保留期 |

## 执行规则

- 资产清单为每个有状态资源登记备份方式、频率、保留期和恢复责任人。
- 备份与原始数据使用不同的故障边界；需要防误删或防篡改时启用相应保护功能。
- 每月检查备份作业结果；每季度至少抽取一项关键数据做恢复验证。验证结果记录耗时、恢复点、缺失项和改进措施。
- 生产数据复制到 Dev/Test 前，先由 APP 层完成脱敏与访问审批。

## 当前核查重点

`weekly-report` 的输入 DOCX、生成 PDF 和下载附件需要确定实际存储位置与保留期；现有仓库无法证明其已被备份。SharePoint 数据的恢复能力应按 Microsoft 365 的实际策略单独核对。
