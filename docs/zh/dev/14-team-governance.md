# 团队职责、规范例外、评审与更新

每个应用和共享平台都要有明确负责人。负责人维护对应文档、门禁和发布记录；即使实施工作由其他人完成，责任也不能悬空。

## 职责分工

| 角色 | 主要责任 |
| --- | --- |
| 业务或产品负责人 | 确定需求优先级、验收标准和正式发布窗口 |
| 技术负责人 | 架构与代码质量、关键 PR 评审、技术债和版本兼容 |
| 开发人员 | 实现、测试、文档更新、PR 自检与缺陷修复 |
| 测试或验收负责人 | 维护测试范围、Test 验收及缺陷结论 |
| 平台与运维负责人 | GitHub、ACR、共享环境、部署权限、监控及恢复演练 |
| 安全负责人 | 身份、密钥、依赖风险和安全例外的评估 |

小团队可由同一人承担多个角色，但生产发布审批和关键改动复核应有第二人参与。人员变动时，按[开通与回收流程](./04-access-and-onboarding.md)交接系统、权限、待办与值班信息。

## 规范变更

本规范纳入公司 GitHub 仓库后通过 PR 修改。提案应说明背景、影响范围、迁移步骤及生效时间；相关应用、平台或安全负责人评审。涉及破坏性变更时，先在 Dev/Test 验证，再通知受影响团队。
